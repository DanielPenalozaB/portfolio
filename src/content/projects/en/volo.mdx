## Status

Volo is a concept. I've worked out the problem, the features, the screens and the architecture, but I haven't built it yet, so everything below describes the plan.

## The idea

Volo is a mobile gym companion meant to take the guesswork out of training. In one app, you'd build structured routines, follow exercise tutorials that show which muscles each exercise works, track what you eat, and chart your weight over time. The goal is that you shouldn't need a personal trainer to find your way around a gym.

## The problem

Most people who go to the gym run into the same frustrations:

- Without a plan, workouts end up random and don't get results
- There are hundreds of exercises, and it's hard to know which ones target what you need
- Routines, nutrition and progress usually live in separate apps
- Without tracking your weight over time, you can't tell whether you're improving

I want one app that handles all four, with a clean mobile interface and nothing to distract you.

## Planned features

### Routines by body section

Users would build routines around the muscle groups they want to work:

| Section | Example Exercises |
| ------- | ----------------- |
| **Push** | Bench press, overhead press, tricep dips |
| **Pull** | Deadlift, barbell rows, pull-ups |
| **Legs** | Squats, leg press, Romanian deadlifts |
| **Core** | Planks, cable crunches, hanging leg raises |
| **Arms** | Bicep curls, skull crushers, hammer curls |

Each routine would support a custom exercise order, sets, reps and weight for each exercise, a rest timer between sets, and notes.

### Exercise library with tutorials

Each exercise would include step-by-step instructions, animated diagrams of the primary and secondary muscles it works, common mistakes, and alternatives for when you don't have the right equipment.

### Nutrition and weight

Daily food logging with a breakdown of protein, carbs and fats, calories against a daily target, and quick-add for frequent foods. A separate weight log would draw a trend line that smooths out daily fluctuations, with weekly averages and goals with a projected timeline.

### Workout mode

Starting a routine would switch the app to a focused workout screen:

```
┌─────────────────────────────┐
│  Bench Press          3/4   │
│  ─────────────────────────  │
│  Set 1: 80kg × 10 ✓        │

│  Rest: 1:23 remaining       │

```

## Planned architecture

| Technology | Role |
| ---------- | ---- |
| **Flutter** | Cross-platform mobile UI framework |
| **Dart** | Application logic and state management |
| **FastAPI** | Python backend for API and data processing |
| **PostgreSQL** | Database for users, routines, and exercise library |
| **SQLite** | Local device storage for offline support |
| **Matplotlib** | Server-side progress chart generation |

```
┌──────────────────┐     ┌──────────────────┐     ┌──────────────┐
│   Flutter App    │────▶│   FastAPI        │────▶│  PostgreSQL  │
│   (iOS/Android)  │◀────│   /api/v1/*      │◀────│              │
└────────┬─────────┘     └──────────────────┘     └──────────────┘
         │
         ▼
┌──────────────────┐
│   SQLite Local   │
│   (Offline Cache)│
└──────────────────┘
```

The app would work offline first. Gyms often have bad reception, so routines and exercise data would be copied to a local SQLite database, and workouts would sync when the connection comes back.

The approaches I plan to use for the hard parts:

- Sync: last-write-wins with timestamps, a `synced` flag on local records, and a background isolate that retries periodically. Creating routines and logging sets would never wait on the network.
- Muscle diagrams: SVG body maps where each muscle group can be colored on its own, so one set of drawings covers every exercise.
- State: Riverpod, with the active workout saved to local storage so it survives the app being closed mid-session.
- Rest timer: compute the remaining time from a saved start timestamp instead of counting down, with local notifications when the app is in the background.

## Draft data model

```python
class Routine(BaseModel):
    id: UUID
    user_id: UUID
    name: str
    section: str  # "push" | "pull" | "legs" | "core" | "arms"
    exercises: list[RoutineExercise]

class RoutineExercise(BaseModel):
    exercise_id: UUID
    order: int
    sets: int
    target_reps: int
    target_weight: float | None
    rest_seconds: int

class WorkoutLog(BaseModel):
    id: UUID
    routine_id: UUID
    started_at: datetime
    completed_at: datetime | None
    sets: list[SetLog]

class SetLog(BaseModel):
    exercise_id: UUID
    set_number: int
    weight: float
    reps: int
    completed_at: datetime
```
